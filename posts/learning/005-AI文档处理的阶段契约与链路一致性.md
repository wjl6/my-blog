# AI 文档处理的阶段契约与链路一致性

同一份 PDF，在调试页能找到目标，正式执行却漏掉；反过来，正式结果又出现调试时没有的区域。这类差异不一定来自模型能力，也可能来自两条链路处理了不同页面、裁图、文字批次，或者把不同阶段的产物当成最终结果比较。

排查的关键是为每个阶段建立契约：输入是什么，覆盖到哪里，允许产生哪类结果，由谁决定接受，以及哪些变化会让缓存失效。下面使用完全模拟的文档、文字和尺寸说明设计方法，验收表描述预期行为，不代表模型准确率或性能测量结果。

## 一 先让两次执行具备可比较的条件

文件名和页面外观不足以确认输入一致。原件、转换件、当前预览件可能具有相似内容，却有不同字体、文字层和页面几何。应对实际送入处理器的字节计算内容摘要，再记录页数、提取器与渲染器版本、模型配置、规则和提示词版本。

输入相同之后，还要比较执行范围。调试只运行一个文字批次，正式任务处理全部批次；调试查看一张裁图，正式流程额外处理整页；两者都调用同一函数，也不意味着执行范围相同。可用如下简化清单表达约定，字段仅为演示设计：

```json
{
  "input_digest": "<SYNTHETIC_FILE_SHA256>",
  "pipeline_revision": "demo-pipeline-r3",
  "policy_revision": "demo-policy-r2",
  "model_revision": "demo-vision-r1",
  "coverage": {
    "pages": [1, 2],
    "text_batches": "all",
    "image_scope": "whole-page"
  },
  "comparison_stage": "final-admission"
}
```

配置签名应涵盖实际生效值，包括供应商路由、图像预处理和采样参数；密钥只记录受控的版本标识，不能进入日志。摘要与签名约束比较条件，不能保证模型输出确定。需要检查下游逻辑时，固定一次模型响应做离线重放，将重新采样的差异与代码变化分开。

## 二 坐标需要携带完整的变换关系

一个矩形至少要说明页标识、原点、单位、旋转状态和参考区域。页面坐标、整页渲染像素、裁图像素、上传后图像像素是不同空间，归一化到 0 至 1 也不会自动消除这种区别。

例如 PyMuPDF 的页面方法从 1.17.0 起使用未旋转页面坐标，`Page.rect` 与 `Page.bound()` 等有例外；与旋转显示交互时需核对对应的旋转和逆旋转矩阵。[PyMuPDF 页面坐标约定](https://pymupdf.readthedocs.io/en/latest/page.html)

一个完全模拟的无旋转例子：页面以左上为原点，尺寸为 `400 × 600 pt`，整页渲染为 `800 × 1200 px`。从整图的 `(200, 400)` 起截取 `400 × 400 px`，再缩为 `200 × 200 px` 上传。矩形四值约定为两角坐标 `[x0, y0, x1, y1]`，OCR 在上传图上返回 `[20, 30, 60, 50]`，则：

```text
撤销上传缩放： [40, 60, 120, 100]
加回裁图偏移： [240, 460, 320, 500]
撤销整页缩放： [120, 230, 160, 250] pt
```

此处假定没有改变页面裁剪区域，也没有自动纠偏。存在旋转、非零裁剪偏移或 OCR 自动转正时，应按实际处理顺序逆向组合变换，转换矩形四角或原始多边形，再决定是否需要矩形近似。PDF 原生坐标与 MuPDF 的原点、纵轴方向也不同，不能混用。[PyMuPDF 坐标与变换说明](https://pymupdf.readthedocs.io/en/latest/app3.html#coordinates)

转换后的坐标必须检查有限值、边界和有效面积；来源尺寸或变换缺失时保留未决状态。拿截图宽高直接除页面尺寸，可能得到看似合法但位置错误的框。

## 三 为不同来源的证据设置准入条件

原生文字、OCR、规则和模型应保留独立来源，不能把它们的输出简单求并集。

| 来源 | 能提供什么 | 不能单独推出什么 |
| --- | --- | --- |
| 原生文字 | 原字符、字符或词块位置 | 该文字应被处理的语义类别 |
| OCR | 图像中的文字与位置 | 识别内容、人物归属一定正确 |
| 规则 | 可解释的格式或上下文线索 | 相似格式一定属于目标字段 |
| 视觉模型 | 布局、语义及关联关系候选 | 裸矩形已具有可靠文字依据 |

以模拟文档中的“演示联系人”为例，模型认为某处是姓名，仍应核验候选值能否对应原文、位置是否明确、上下文是否满足策略。标题、页脚或示例字段的重复出现，不能单凭字符串相同就升级为全局身份。

语义置信度和定位质量应分别保存。知道“这里可能是姓名”不代表已经知道应处理哪些字符；位置精确也不代表类别正确。不同任务可采用不同准入策略，但应明确哪些规则足以直接接受，哪些只能生成待确认线索。

整页与裁图也应标明来源。裁图里没有某个对象，不能证明整页不存在；额外增加裁图分析后，新增候选仍须经过同样准入，不能因调用次数增加而自动提高可信度。

## 四 比较同一阶段的产物并记录覆盖缺口

“模型提出候选”“候选完成定位”“候选通过最终准入”和“结果已持久化”应是不同产物。调试界面应显示当前阶段，正式接口也应保留最终结果与人工草稿的边界，避免拿中间候选数与页面展示数直接比较。

每个阶段的检查点至少包含输入签名、已完成的页面与批次、输出引用、未决项和受控原因码。若文档预期处理四个批次，只成功三个，则三个批次各自成功仍不能推出文档覆盖完整。跨页判断依赖的上下文也属于覆盖范围。

候选未进入最终结果时，记录它在哪个阶段被拒绝，以及原因是原文不符、定位歧义、策略排除，还是前置阶段失败。运行日志默认只写候选身份、阶段、耗时和原因类别；正文、图片、完整提示词和模型响应放在受控存储中，按权限与期限管理。

传输成功与内容完整也需要分别表达。调用正常返回但部分页面失败，应显示部分完成及缺口；任务执行异常则保留失败阶段。没有候选既可能是确认无目标，也可能是识别未完成，两种结果必须可区分。

## 五 去重要保留实际出现位置和定位质量

同一段文字在两页出现，应保留两个位置。同一页中，原生文字与 OCR 指向同一处内容，则可以归并证据，避免重复框；不能因为它们的块 ID 不同，就认定互相矛盾。

归并应同时检查页面、可比较的文字、坐标重合和局部上下文。只按文本去重会丢掉重复出现的位置，只按矩形交叠则可能误合并相邻字段。对两个人的同名、同格多个值等歧义，优先保留独立候选或交给复核。

粗框与精确字符框不能简单取外包络，否则后到的粗框可能把已确定范围扩大到旁边内容。可以归并来源与语义证据，同时保留精确定位为主结果；粗框只作未决定位线索。关联判定与最终去重还应使用一致的坐标基础，避免同一对象先被当成两个人，后来又合成一个位置。

## 六 规范化匹配时保留原文索引映射

PDF 文字层可能包含兼容字符或连字，视觉一致的字符串不一定具有相同码点。Unicode 的 NFKC 会折叠部分兼容差异，例如把连字展开；这种处理并非所有标识符和业务字段都语义等价，应按字段策略选择。[Unicode 规范化形式](https://www.unicode.org/reports/tr15/tr15-58.html)

以模拟文字 `ofﬁce` 为例，`ﬁ` 是一个连字字符，规范化后成为 `fi`。如果直接用新字符串的索引截取旧字符框，后面的坐标就会错位。因此匹配视图与定位视图应分开：匹配使用规范化文本，定位通过映射回到原始字符区间和几何信息。

映射可能一对多、多对一，也可能涉及组合字符的重排，不能假定长度不变。逐字符独立规范化再拼接也不总等价于整段规范化，边界组合需要正确处理。[Unicode 规范化与字符串拼接](https://www.unicode.org/reports/tr15/tr15-58.html#Concatenation)

实现可以采用支持来源映射的文本变换，或在受控片段内维护规范化结果到原文区间的对应关系。无法可靠映射时，退回词块级定位并标记粒度，不能伪造单字精度。去重和回扫复用同一匹配策略，但不能因此覆盖或丢弃原文。

## 七 缓存复用要服从依赖和覆盖契约

成功批次可以复用，但缓存键不能只有文件名。至少要纳入实际输入摘要、上游产物签名、页面与批次范围、预处理、模型与提示词、策略及相关配置版本。模型、上下文或批次切分改变后，应重新判断哪些下游产物仍有效。

OCR 已成功而语义判断失败时，可以复用有效 OCR，只补失败或未决的判断；整页仅有部分疑点时，也可设计局部补充流程，但必须保留它依赖的全文上下文。补充结果仍走统一准入与合并流程，不能绕过校验。

重试同时限制次数、总截止时间和并发。超时后旧请求可能仍在执行，接收结果时应核对当前输入和执行轮次；同一逻辑操作的身份不应在每次重试中变化。幂等身份相同而参数不同，需要拒绝混用。[AWS 幂等重试设计](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)

减少重复计算是否有效，需要分别观察缓存命中、外部调用数、排队、计算耗时和覆盖缺口。提高并发上限不保证缩短单份文档耗时，也可能挤占其他任务资源，应在隔离样本与预算下验证。

## 八 用模拟边界场景验收链路一致性

验收应固定模拟文档、执行清单与比较阶段；检查下游逻辑时固定上游响应，评估模型时再单独重复采样。

| 模拟场景 | 预期行为 |
| --- | --- |
| 同名文件的实际字节不同 | 摘要区分输入，旧缓存不混用 |
| 整页、多裁图与多文字批次执行 | 显示各自范围，缺失批次不能算完成 |
| 页面旋转、裁剪、上传缩放 | 转换后位置与原图一致，未知变换阻止直接采用 |
| 同文字出现在两处，同一处有两种来源 | 保留两处出现位置，同位来源归并 |
| 精确框之后到达相交粗框 | 保留精度，不无条件扩大区域 |
| 连字、兼容字符与组合字符 | 匹配后正确回到原字符，歧义明确可见 |
| 一个批次超时，其他批次成功 | 复用有效产物，保留未决状态与重试预算 |
| 空结果、候选拒绝、持久化失败 | 原因与覆盖范围可追踪，不统一显示成功 |

两条链路应共用识别、定位、准入与合并实现，调试入口只选择运行范围和停留阶段。把这些选择显式记录下来，才能解释结果差异，并逐步修正真正发生偏离的阶段。

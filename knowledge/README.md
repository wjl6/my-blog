# 主题知识

按“原理、问题方案、专业术语”组织长期知识，方便从主题、关键词或关联链接查找。每条内容只维护一份正文，同一主题已有条目时优先补充更新。

| 内容 | 首次写作时创建的路径 | 模板 |
| --- | --- | --- |
| 专题笔记 | `notes/<topic>/<三位编号>-<中文主题>.md` | [专题模板](../templates/note.md) |
| 问题与方案 | `solutions/<topic>/<三位编号>-<中文主题>.md` | [方案模板](../templates/solution.md) |
| 专业术语 | `glossary/<topic>/<三位编号>-<中文主题>.md` | [术语模板](../templates/term.md) |

主题优先使用 `backend`、`frontend`、`database`、`middleware`、`architecture`、`ai`、`devops`、`tools`，在有第一篇真实内容时创建。跨主题内容选一个主目录，其余用标签和链接表达。

## 专题笔记

回答“是什么、为什么、怎样用、何时适用”，保留核心原理、最小示例、取舍、版本与参考来源。按知识点拆分；不需要把同一技术的所有内容塞进一个持续膨胀的文件。

## 问题与方案

回答“出现什么现象、证据是什么、根因是什么、怎样处理和验证”。尚未确认的根因标记为假设，保留草稿状态，说明下一步。不同根因的问题分别记录，通用原理链接到专题笔记。

## 专业术语

记录中文名、英文全称、缩写、自己的解释、实际例子和易混概念。同一术语更新原卡片，在 `aliases` 中补充检索别名；长篇实践链接到方案或文章。

完整命名、元数据与图片规则见[目录规范](../docs/directory-design.md)，已有面试资料保留在 [posts/interview](../posts/interview/)。

# 结构化导出的来源映射与校验诊断

表单生成 XML 后，一条“某行不符合约束”的错误，通常还不足以指导使用者修改。字段可能经过转码、合并与重排，错误也可能在父节点或结束标签处才被发现。可靠的提示需要同时回答：错误属于哪份文件、源于哪些输入、还能否用于当前表单。

以下给出一套通用设计，适用于 XML 1.0 与 XSD 校验，不依赖 XSD 1.1 特有能力。示例字段、数据与诊断均为完全模拟；验收表描述预期行为。

## 一 保留来源身份和生成位置

导出至少连接三个对象：源字段、生成结构、具体文件版本。生成器写出节点时，同步生成独立的来源映射（source map），避免事后仅靠 XML 文本反推表单。

| 信息 | 用途 | 不能替代什么 |
| --- | --- | --- |
| 稳定字段键与源路径 | 识别字段，定位生成时的输入位置 | 显示名称不能代替稳定字段键 |
| 重复行稳定身份 | 数组插入、删除、排序后仍能识别同一行 | 数组下标只表示当时位置 |
| 元素或属性身份、命名空间与出现位置 | 区分同名节点和多次生成 | 简化路径不能忽略命名空间 |
| 生成版本与最终文件摘要 | 确认映射对应哪份实际文件 | 批次显示号不能代替唯一生成身份 |

一个节点可能由多个输入共同决定；一个字段也可能生成多处节点。映射应允许多对多，并区分源值、默认值、字典转换和计算结果的来源，不要求修改对外 XML 来塞入内部行标识。

下面的 JSON 与 XML 仅演示“数量”字段的转换：

```json
{
  "entries": [
    {"rowKey": "demo-row-002", "count": -1}
  ]
}
```

```xml
<package xmlns="urn:example:export">
  <entry><count>-1</count></entry>
</package>
```

假设模拟 XSD 将 `count` 声明为非负整数。来源映射保存 `count` 的稳定字段键、`demo-row-002`、生成时路径 `entries[0].count` 及对应节点；校验后才有条件将提示关联到该行的“数量”。XML 中没有暴露内部行键。

## 二 用同一版本集合生成文件与诊断

同一份源 JSON，经不同模板、字典或生成器处理，可以得到不同 XML。生成记录应绑定输入快照、模板版本、字典快照、生成器版本，以及影响输出的时区、默认值等参数；诊断再绑定实际输出摘要、整套 XSD（含导入依赖）与业务规则版本。

这些内容可以构成确定序列化后的指纹。采用 JSON 规范化方案时，应明确数字、字符串及属性顺序的处理；不能为消除差异而任意重排数组。RFC 8785 的 JCS 会确定对象属性顺序，同时保留数组顺序，但也有自己的输入限制，不能简单等同于任意 JSON 序列化。[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)

指纹只帮助识别参与计算的内容，不会使跨存储读取自动获得一致性。应先取得可复用的版本快照，再执行生成和校验；若过程中使用了变化中的字典，不能仅凭最后一次计算的摘要宣称版本一致。

来源映射、位置索引与校验必须对应同一份最终 XML。校验后再次缩进、换行或改写文件，会使原行列定位失效；改变内容后应重新建立位置索引并校验。

## 三 将行列作为线索而非字段身份

解析器报告的位置不一定是错误字段的起点。以 Java SE 21 的 `SAXParseException` 为例，其行列描述的是引发异常文本末尾的位置；不能直接把它解释成源表单路径。[SAXParseException](https://docs.oracle.com/en/java/javase/21/docs/api/java.xml/org/xml/sax/SAXParseException.html)

定位时先核对文件摘要，再查生成节点的位置范围和来源映射。缺少必填子节点、元素顺序错误或跨节点约束，可能只能定位到分组甚至整个文档。此时保留全局摘要及相关位置，让使用者检查结构，不强行给某个相邻字段标红。

XML 注释可以辅助人工阅读，但不能承担唯一映射依据。注释可能在不同位置出现，处理器也不必向应用提供注释文本；“取报错行之前最近的注释”可能把相邻节点错误归属到同一字段。[XML 1.0 注释语义](https://www.w3.org/TR/xml/#sec-comments)

## 四 分开结构校验与语义校验

| 校验层 | 示例问题 | 提示范围 |
| --- | --- | --- |
| 输入与转换 | 必填源值缺失、字典未命中、转换方向错误 | 已知源字段及来源 |
| XML 与 XSD | 不合法文本、类型、节点顺序或出现次数 | 可靠定位的字段、分组或全局 |
| 业务语义 | 码值虽合法却代表另一含义、跨字段组合不成立 | 规则涉及的多个字段 |

XSD 能表达类型、枚举、出现次数以及部分键与引用约束，不能笼统认为它只检查“格式”。但仅通过已经声明的约束，无法证明外部字典选对或业务含义正确；规则未写入任何校验层时，就不会自然得到验证。[W3C XML Schema 入门](https://www.w3.org/TR/xmlschema-0/)

诊断结构应分别保存校验阶段、规则标识、严重级别、中文说明、来源引用、XML 位置与定位状态，不用翻译后的错误文本充当关联键。界面展示可读名称，展开后再提供技术路径；日志与提示不默认复制源字段原值。

## 五 限定诊断何时可以影响当前表单

一条错误存在于历史文件中，并不表示当前输入仍然错误。应用诊断前应同时核对当前生成身份、输入与配置指纹、结果所用文件摘要，以及页面是否有未保存编辑。

| 状态 | 界面处理 |
| --- | --- |
| 当前且上下文一致、来源唯一 | 定位字段或重复行，显示错误说明 |
| 输入或配置变化、存在未保存草稿 | 标记诊断过期，停止沿用旧标红 |
| 无法可靠定位 | 保留全局摘要与可用结构位置 |
| 校验未完成、失败中断或没有结果 | 显示未知，不能显示为通过 |
| 历史结果或仅有旧文本诊断 | 在独立历史视图展示，不猜测当前字段归属 |

历史详情应加载对应的输入、模板与文件快照；没有保存旧快照时，明确哪些信息无法还原，不用当前配置拼出看似完整的历史。旧文本诊断不能冒充结构化定位结果；重新生成得到新版本，旧记录继续保留原来的含义。

## 六 防止迟到响应重新激活旧错误

请求发出时保存当前输入版本和选择的生成身份，响应到达时再次核对。仅在请求仍是当前有效请求、页面未切换版本且上下文仍匹配时更新标记。取消请求可以减少等待，不能代替响应到达后的身份检查。

例如，检查 A 尚未返回时，使用者修改数量并生成 B。即使 A 最后返回，也只能更新 A 的历史结果，不能覆盖 B 的详情或给新输入标红。后端若需要更新“当前生成版本”指针，同样使用版本条件保护。

网络重试应明确是读取或重试同一生成快照，还是依据变化后的输入创建新版本。前者按生成身份复用结果，后者分配新的生成身份；不要让“重试”悄悄改写原文件，使历史诊断与下载内容失去对应关系。

## 七 用模拟变更验收诊断生命周期

| 模拟场景 | 预期结果 |
| --- | --- |
| 数量违反模拟类型约束 | 关联唯一来源，保留中文说明与技术位置 |
| 错误行前插入新行 | 旧诊断先过期；重新生成后按稳定行身份定位，不沿用旧数组下标 |
| 源值未变，字典或模板变化 | 旧诊断过期，重新生成与校验 |
| 缺失父节点或出现多个候选来源 | 降为分组或全局提示，不武断归属 |
| A 请求晚于 B 返回 | 当前详情与标记仍属于 B |
| 查看历史文件、再编辑当前草稿 | 历史可独立查看，旧错误不进入草稿 |
| 只有文本诊断或校验中断 | 显示定位不可用或未知，不伪造通过结论 |

验收应固定模拟输入、模板、字典、校验规则及序列化方式，分别检查文件内容、来源映射、诊断记录和界面状态。可靠的字段提示来自这些对象之间可核对的关系，而非一条错误文本或一组红色样式。

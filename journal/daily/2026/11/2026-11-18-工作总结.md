# 2026年11月18日工作总结

## 今日进展

- **PDF 预览与资源释放。** 连续预览改为渲染视区附近的页面，离开视区后释放画布和页缓存。页面退出时取消在途列表请求，轮询改为串行，后台标签页暂停发起新轮询。用同一份 16 页模拟 PDF 在 Chrome 对比，活跃画布从 16 张降到 3 张。已核对多标签页、路由切换和刷新，前端构建通过。整页内存仍需复测，双栏比对仍可能因整篇渲染而出现较高峰值。
- **XML 投递与迁移恢复。** 补齐失败补偿记录、暂存文件清理和回执版本校验。提交结果不确定时保留原请求，通过投放记录和回执核对结果。增量迁移遇到 MySQL 行大小限制，已修改脚本，用 `TEXT` 存储长诊断说明，并兼容部分步骤已执行的状态。前端构建、模拟浏览器流程及 Java 语法检查通过。修订脚本重跑、共享卷投放和实际回执仍待验收。
- **输入转换与检索授权。** 同义词映射按模板和字段生效，记录原值与命中依据，保留人工确认结果。检索条件支持分组授权，服务端校验条件权限和导出会话归属。权限变化后，旧查询快照失效。预设中有不可用条件时，等用户确认剩余条件再执行，以免筛选条件减少后扩大结果范围。已完成代码和静态核对，真实角色权限与下载链路仍待验收。

## 技术收获

1. **内存问题按资源生命周期验证。** 固定输入，重复执行进入、滚动、离开和刷新操作，分别观察画布数量、页面内存和多轮操作后的回落情况。画布变少验证了渲染范围收敛，浏览器的整体占用需独立采样。
2. **失败恢复先核对持久化证据。** 投递中断后，用同一请求身份核对回执。迁移中断后，以数据库实际列状态决定哪些步骤还需执行。MySQL 8.0 的行大小检查包含列定义的存储预算，字符集也会影响计算。对于长诊断文本，可用 `TEXT` 降低该列计入行大小的开销。[MySQL 8.0 行大小限制](https://dev.mysql.com/doc/refman/8.0/en/column-count-limit.html)

- 在隔离环境验收增量脚本重跑、投递中断后的恢复、迟到回执和权限撤回后复用旧会话的行为。

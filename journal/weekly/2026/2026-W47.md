# 2026年第47周工作复盘

周期：2026-11-16 至 2026-11-22，周一至周日。进展截至 2026-11-20。

本周最有价值的进展，是把邮件同步、文件投递和报表导出中的“完成”拆成可以分别核对的结果。已落地的修复、样例验证和实际环境验收分开记录。

## 本周成果

| 方向 | 结果与证据 | 待验证边界 |
| --- | --- | --- |
| 邮件拉取与补偿 | 完成 IMAP 方案，明确发现、下载快照、解析和提交的职责。继承现有失败登记与退避保护，本周补齐异常地址头的回退，保留可读部分并继续处理正文和附件。 | 当前检查点仍可能被失败件拖住；历史漏件、误去重和内容不全的实际影响须逐封核对。方案中的发现与处理分离尚未整体落地。 |
| XML 生成与交付 | 将生成版本、投放请求和回执关联起来，统一收发身份规则并保留历史文件身份。样例通过 XSD，模拟附件完成字节对照；对照排查发现，通过相同结构校验的文件仍可能被接收端区别处理。 | 接收端业务校验、拒收根因、共享卷投放及迟到回执尚未贯通；修订后的数据库迁移脚本也待在隔离环境重跑。 |
| 检索与报表 | 旧预设含隐藏条件时，需要确认剩余条件再查询。手动和定时报表共用工作簿逻辑；跨库对账区分查询失败、值缺失与值不一致。通过对比合并的两个父提交，定位了无文本冲突却留下失效权限调用的问题。 | 角色配置、受限账号导出、实际下载、定时发信和重试均待验收。 |
| PDF 预览 | 按视区渲染并回收离屏资源。对同一份 16 页模拟文件，Chrome 中的活跃画布由 16 张降至 3 张；同时核对了多标签页、路由切换和刷新。 | 画布数量只反映渲染资源的一个维度。整页内存峰值、双栏和长文档反复开启后的回落仍待独立测量。 |

## 关键收获

1. **跨系统重试优先核对上一次的结果。** 一次投放提交后如果响应丢失，应保留请求身份，先查投放记录和回执；收到旧回执时，只更新它对应的生成版本。用中断、超时和迟到回执三类模拟场景分别验收。结构校验和业务接收的边界见[结构化导出的来源映射与校验诊断](../../../knowledge/notes/backend/001-%E7%BB%93%E6%9E%84%E5%8C%96%E5%AF%BC%E5%87%BA%E7%9A%84%E6%9D%A5%E6%BA%90%E6%98%A0%E5%B0%84%E4%B8%8E%E6%A0%A1%E9%AA%8C%E8%AF%8A%E6%96%AD.md)。
2. **把缺失、失败和结果未知分开建模。** 邮件正文解析异常不能当作合法空正文，外部查不到数据也要先判断请求是否成功。监控和对账应分开记录这些状态，否则重试可能被去重跳过，报表也可能把技术故障写成业务差异。详见本周整理的[IMAP 邮件可靠拉取与故障恢复方案](../../../posts/learning/006-IMAP%E9%82%AE%E4%BB%B6%E5%8F%AF%E9%9D%A0%E6%8B%89%E5%8F%96%E4%B8%8E%E6%95%85%E9%9A%9C%E6%81%A2%E5%A4%8D%E6%96%B9%E6%A1%88.md)。

## 下周验收重点

- [ ] **邮件补偿**：用隔离邮箱验证异常地址、缺附件、持续重试和检查点恢复；按邮件身份逐件核对原件、正文、附件及下游结果。持续失败的单件要能独立追踪，新件不应被它长期阻塞。
- [ ] **XML 交付**：用模拟文件贯通生成、共享投放、接收诊断和回执；缺失原附件时阻止投递，迟到回执不覆盖新版本。让修订后的迁移脚本从部分执行状态重跑，确认已完成步骤不会被重复应用。
- [ ] **权限与报表**：用受限角色对比列表、手动导出与定时报表各自应有的数据范围，核对月界、重复触发和查询失败。权限变更后，旧查询或导出会话应按当前授权重新校验。
- [ ] **预览资源**：固定长文档、浏览器和操作序列，记录单栏与双栏的资源峰值，以及反复进出页面后的内存回落。
